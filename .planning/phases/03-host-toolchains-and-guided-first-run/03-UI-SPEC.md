# Phase 3 — UI Design Contract

> Visual and interaction contract for the first-run wizard (`gui/firstrun.py`), the "setup is not finished" banner, and the Setup tab additions. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a PySide6 Qt Widgets desktop app (Fusion style, `gui/app.py` `main`), not a web app. Every value below is a Qt term: layout margins and spacing in px, font sizes relative to the application font, colours as palette roles or hex for status glyphs only. Baseline: `.planning/phases/01-bridge-bundles-and-ci/01-UI-REVIEW.md` (14/24). Its findings tagged **(Phase 3)** are answered here.

## Spacing Scale

Applies to widgets this phase creates (`gui/firstrun.py`, the banner, new Setup tab buttons). Widgets that already exist in `gui/app.py` keep Qt's default layout margins: the upstream-sync rule limits edits there to hook lines.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph to text inside a row; between a status line and the fix line under it |
| sm | 8px | `QHBoxLayout`/`QVBoxLayout.setSpacing` inside a row or list; button-to-button gap; banner vertical margin |
| md | 16px | Each wizard page's `setContentsMargins(16, 16, 16, 16)`; gap between blocks on a page (heading block, list, action row); banner horizontal margin |
| lg | 24px | Gap between the page heading block and the page body |
| xl | 32px | Gap above the done page's primary action row |
| 2xl | 48px | unused this phase |
| 3xl | 64px | unused this phase |

Sizes:
- Wizard window: `setMinimumSize(720, 560)`, initial `resize(760, 600)`, parent `win` with `Qt.Window` so it is its own top-level window and closes with the app.
- Primary action buttons (Download all missing, Port a game, Accept and continue): `setMinimumHeight(36)`, the same as today's Port button.
- Every other button: Qt default height.
- Banner: contents margins `(16, 8, 16, 8)`, one line high, the Continue setup button on the right after a stretch.

Exceptions: today's tabs keep Qt default margins (about 9–11 px depending on the host). This is the only exception.

## Typography

`P` is `QApplication.font().pointSizeF()` on the host (about 13 pt on macOS, 9 pt on Windows, 10–11 pt on Linux). Sizes are relative so the wizard scales with the user's system font. No pixel font sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (descriptions, tool and device details, fix text, banner text) | P | Normal (400) | Qt default (`QFontMetrics.lineSpacing`, about 1.2). Do not set `line-height` CSS |
| Mono (commands, paths, hashes, versions in the progress line) | 9 pt fixed (`systemFont(FixedFont)`, `setPointSize(9)`, as the Port log) | Normal (400) | Qt default |
| Primary button | P + 2 | Bold (700) | Qt default |
| Page heading | P + 4 | Bold (700) | Qt default |

Weights: exactly two, `QFont.Normal` and `QFont.Bold` (`setBold(True)`, as the Port button does today). Labels such as tool and device names use Body with `<b>` only inside rich-text labels, which is still Bold (700).

## Color

Fusion follows the system light or dark scheme, so surfaces come from palette roles and are never hard-coded. Hex values are used only for the status glyphs and the banner tint, and each one has a light and a dark value, picked once per paint with `dark = w.palette().window().color().lightness() < 128`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `QPalette.Window` (Fusion light about `#efefef`) | Wizard and window background, page body |
| Secondary (30%) | `QPalette.Base` / `QPalette.AlternateBase` | Tables and lists (tool rows, key candidates, devices, playable titles), line edits |
| Accent (10%) | `QPalette.Highlight` (system accent) | Only the elements listed below |
| Destructive | light `#c62828`, dark `#ef9a9a` | Problem glyph `✗`, the problem word in a status line, and `[RED] ` lines. There is no destructive button in this phase (Copywriting) |

Accent reserved for:
1. The single default button on each page (`setDefault(True)`): Accept and continue (legal), Next (keys, tools, device), Download all missing (tools, while something is missing), Port a game (done).
2. The `QProgressBar` chunk (Fusion draws it in Highlight already).
3. The selected row in the key-candidate and device lists.
Nothing else is accent-coloured. Links in rich text use `QPalette.Link`.

Status colours (glyph and the status word only; the detail text after them stays `QPalette.WindowText`/`Text`):

| Status | Glyph | Light | Dark | Contrast measured |
|--------|-------|-------|------|-------------------|
| ok | `✓` | `#2e7d32` (today's) | `#81c784` | 5.13:1 on white, 6.10:1 on `#353535` |
| problem / required missing | `✗` | `#c62828` (today's) | `#ef9a9a` | 5.62:1 on white, 5.70:1 on `#353535` |
| note / optional missing / community build | `!` or `–` | `#9a5b00` (replaces `#ef6c00`, which is 3.08:1, UI review Color finding) | `#ffb74d` | 5.43:1 on white, 7.09:1 on `#353535` |
| secondary text (source label, sizes) | — | `QPalette.PlaceholderText` (replaces `#757575`) | same role | system-provided |

Banner: background light `#fff4e5`, dark `#3d2e12`, text `QPalette.WindowText`, glyph `!` in the note colour. Measured: `#9a5b00` on `#fff4e5` 4.99:1, `#ffb74d` on `#3d2e12` 7.59:1.

Define these once in `gui/firstrun.py` as `COLOUR = {'ok': ('#2e7d32', '#81c784'), 'bad': ('#c62828', '#ef9a9a'), 'note': ('#9a5b00', '#ffb74d'), 'banner': ('#fff4e5', '#3d2e12')}` with one helper `colour(widget, key)`. Do not edit `STATUS_COLOUR` in `gui/app.py` this phase (hook-lines rule). Colour is never the only signal: every status has its glyph and word.

## Interaction Contract

### Launch and banner (D-01, D-02, D-03, FRUN-02, FRUN-03)
1. On every launch `firstrun.attach(win)` calls `call_json(['setup', '--json'])` (timeout 45 s, `TIMEOUTS['setup']`). The GUI keeps the document in memory only. It writes no file and keeps no "done" flag.
2. `legal.accepted` differs from `legal.version` → the wizard opens at the legal page, non-modal, over the main window.
3. Legal accepted and `ready` false → the banner shows, and the wizard does not open.
4. `ready` true → no banner, no wizard. Soft notes (no adb, no device) show only on the Setup tab and the done page, never in the banner.
5. The banner names only the missing required items, in step order, from the `steps` whose `ok` is false (legal, keys, then the tools items with `required` and not `ok`, then signing key), joined with `, `.
6. **Continue setup** opens the wizard at the first step whose `ok` is false (`setStartId`). Back still reaches the earlier steps (D-04). A second press while the wizard is open raises and activates the existing one: there is never a second wizard.
7. After any wizard action that changes setup (keys saved, download finished, Use my own…, legal accepted), the wizard calls `setup --json` again and the banner and Setup tab redraw from that answer.
8. `setup --json` fails or times out → no wizard, no banner. The Setup tab's `check_msg` shows `failed(fail)` with Retry, and `win.set_ready(False)` is still called (keeps `tests/test_bridge.py:110-118`).

### Wizard buttons
- Bottom row, left to right: **Skip setup** (custom button 1), stretch, **Back**, **Next** (or the page's own primary label), Finish only on the done page, labelled **Close setup**.
- **Skip setup** and the window close box do the same thing: close the wizard. No confirmation, no flag. A running download keeps running: it is `win.setup.fetch` (RESEARCH Pattern 8), so the Setup tab keeps its progress and its **Cancel download** button, and the close guard still covers it.
- Keyboard: Enter presses the page's default button, Esc closes the wizard (same as Skip setup), Tab order follows reading order. Every button has a mnemonic-free plain label (no `&`).

### Page 1: legal (D-07)
- Body: porter's `legal.text` in a read-only, word-wrapped label (plain text), then one link per `legal.links` entry (`<a href>` with the vendor name as text, `QPalette.Link`, opened by `QDesktopServices`). The GUI holds no notice text and no version number of its own.
- Default button **Accept and continue** → `call_json(['config', 'legal', str(version), '--json'])` → `setup --json` → next page. While the call runs the button is disabled and reads `saving…`. A failure shows `failed(fail)` under the text with Retry and stays on the page.
- Skip on this page means the wizard opens again next launch. The body ends with the line in Copywriting that says so.

### Page 2: prod.keys (D-05, D-06)
- Candidate list from `steps[keys].found`: one row per file, `✓`/`✗` glyph, the path in Mono, then `detail` (`keys up to generation 19` or `missing: header_key`). Selecting an ok row saves it (`config keys <path> --json`, then `setup --json`).
- **Browse…** is always present beside the list. A picked file goes through the same save and re-check. The result line under the list shows porter's verdict for the configured file.
- Never shows key values, never copies the file. Next is enabled whatever the result (never blocking).

### Page 3: tools (D-09, D-12, D-13, D-21..D-27, TOOL-01..03)
- Table columns: glyph, Tool, Version, Source, Size or note, action. One row per `steps[tools].items` entry.
  - Source is porter's label as-is: `configured`, `PATH`, `known place`, `Android SDK`, `downloaded`, `env`.
  - Size is `size(download.size)` when porter offers a download, empty when found. A `.NET` size of 0 shows `about 200 MB`.
  - `note` (the community NDK label, the adb `-Z` note) is a second line in the row, note colour, `!` glyph.
  - `fix` of a not-ok row is a second line, Body, with any command in Mono and selectable (`Qt.TextSelectableByMouse`).
  - Action column: **Use my own…** on a missing or not-ok row (folder picker for the NDK, file picker for dotnet and adb) → `config <key> <path> --json` → `setup --json` → the row redraws with porter's verdict. On Linux arm64 with no adb: the row's fix is the distro command, and the action column holds **Copy command**, **Re-check** and **Use my own…** (D-25).
- **Download all missing** (default, primary, with the total size in its label) runs `win.setup.fetch.start(['tools', '--download', '--progress', 'json'])`. It is hidden when `steps[tools].downloadable` is empty. The vendor-license dialog is gone (D-07): one press starts the download.
- While running, the button becomes **Cancel download** (not default, not accent, the same label as the Setup tab's button for the same action), calling `fetch.stop()`. The status line reads `stopping…` until `finished`, then `cancelled. Download all missing resumes where it stopped.` (Phase 1 D-05/D-09 semantics).
- Progress line (Body, word-wrapped, under the table): `[k/n] <name> · <step> · <done> / <total> · <speed>/s · <time left>`. Built with today's `size()`. Speed is `(total - done) / eta` in the GUI (RESEARCH Open Question 1, no protocol change). Time left is `less than a minute left`, `N min left`, or `N h M min left`. Parts with no data are dropped (`' · '.join(filter(None, …))`, UI review Copywriting finding). The bar shows the current file (`frac`), and `[k/n]` shows the batch.
- When the download run ends with `0` and .NET is ok, **Prepare .NET tools** starts automatically on the same `fetch` with the same progress line; the button reads **Cancel .NET preparation** while it runs and calls `fetch.stop()`. When .NET was already there, the row's action column has a **Prepare .NET tools** button instead. A failed Prepare is a note row with porter's fix, never a blocker (D-24).
- Failure: the status line turns into the cause in the problem colour plus `Open log` (today's `fetched()` pattern), escaped, word-wrapped. Hash mismatches show porter's text with both hashes unchanged, in Mono.

### Page 4: device (D-14, D-15, DEV-01)
- Three numbered instructions (Copywriting), then the device list.
- Polling: on `initializePage` and every 2.5 s after the previous answer, `call_json(['devices', '--json'])`. Stops on leaving the page or closing the wizard. A one-shot that fails shows its cause in the list's empty row and polling continues.
- Each device row: glyph (`✓` for `device`, `✗` for `unauthorized`/`offline`/`no permissions`, `▶` for `authorizing`/`connecting`), model or serial, the raw adb state in Mono (testers quote it in reports), then porter's `fix` on a second line.
- Several devices in `device` state: selecting one saves it (`config device <serial> --json`). One device: no selection needed.
- Next is always enabled. Its label is **Next** with a device, **Skip: install later** without one.

### Page 5: done (D-20, D-28)
- Summary list, one row per step with its glyph and `detail`, then each `notes` entry with `!`.
- **Games that play today**: names from `profiles --json` where `status` is `playable`, sorted, plain list. With no playable title, or when `profiles --json` fails, the heading and list are hidden.
- Linux only, and only when porter reports the bundle as frozen: **Add to app menu** → `call_json(['desktop-entry', '--install', '--json'])` → the line `Added to the app menu.` or the failure cause. While the call runs the button is disabled and reads `saving…`. Nothing is written until pressed.
- **Port a game** (default, primary) closes the wizard, switches to the Port tab and calls `PortTab.pick_folder()`. **Close setup** just closes it.

### Setup tab additions (D-04, D-21, D-26)
- `SetupTab.check` reads `setup --json` and renders `doc['checks']` with today's code.
- **Run setup** button at the right of the Requirements group's first row: opens the wizard at the first not-ok step (same as Continue setup), or at the done page when every step is ok.
- Download row: `dl_btn` reads **Cancel download** while a download runs and **Cancel .NET preparation** while Prepare .NET tools runs (the same labels as the tools page), and calls `fetch.stop()`. `dl_step.setWordWrap(True)`. The progress text uses the same format as the tools page. These close UI review Top fix 3.
- Soft notes (no adb, no authorized device) show as a `!` row in the checklist and never trigger the banner.

## Copywriting Contract

Plain English. Players never see the word "porter": use "nx2android" (UI review Copywriting finding). Fix text names the exact command. Problem lines in logs start with `[RED] ` (porter's rule; the GUI strips it and colours the line).

| Element | Copy |
|---------|------|

| Primary CTA (tools page) | Download all missing (`<total size>`) |

| Legal heading | Before you start |
| Legal footer (under porter's text) | Skip setup closes this window. It opens again next time until you accept. |
| Keys heading | Your prod.keys |

| Keys empty state | No prod.keys found in the usual emulator folders. Choose your file with Browse…. |

| Tools heading | Tools for building the app |

| Device heading | Connect your Android device |

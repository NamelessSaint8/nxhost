<objective>
Make `porter port --platform both` a real one-run, two-target driver: Android first, the Mac app second, sharing extraction and the shader split, with per-target results and a non-zero exit when any target failed.

Purpose: this is the protocol half of QUAL-13 and the foundation the GUI (plan 11-02, 11-03) reads. Without it the Port view has nothing to draw a row from and no way to fail one target without losing the other.
Output: `Port.run_both()`, `TargetSkipped`, `--platform both`, `platform` on the JSON stage events, `result.targets[]`, and the exit-code contract — all covered by a new `Both` test class.
</objective>

## Assumptions surfaced (unresolved probe edges)

- **QUAL-13 / ordering** — assumption: the run order (Android, then the Mac app) wins over any argv or tickbox order. What would settle it: the `targets[]` order assertion in `test_both_runs_android_then_mac`, plus a Mac run where the player ticked `Mac app` first.
- **QUAL-13 / concurrency** — assumption: one process, one lock, two sequential children; a second `porter port` on the same folder still refuses with "already running" (Phase 2's lock). What would settle it: `test_both_takes_the_lock_once` (patched `porter.lock.take`, `call_count == 1`) and a manual second run during a `both` run.
- **QUAL-13 / unclassified (needs a human decision)** — assumption: the contract is the pair (exit code, `targets[]`), not a human-readable line. What would settle it: the user's confirmation during `$gsd-verify-work` that `finished in <took>: the Mac app failed` over a working APK is the desired outcome.

## Decision recorded (assumption-delta advisory)

The phase introduces a singular→plural identity change (one target → two, `--platform both`). The identity-model question is: does a `both` run's `result` keep today's flat `apk` / `data` / `app` keys, or become `targets[]`-only? **Recorded decision: additive — the flat keys stay**, filled from whichever targets built, with `targets[]` beside them. Why: `gui/app.py`'s `install_now()` reads `result['data']` and `result['apk']` (Pitfall 7), the golden fixtures pin the single-target shape, and `11-UI-SPEC.md` line 307-310 states `targets[]` is present only for a multi-target run. Not blocking; if a later phase wants `targets[]`-only, `install_now()` must first read the Android entry.

## Trust Boundaries

| Boundary | Description |

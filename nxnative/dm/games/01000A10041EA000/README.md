# The Elder Scrolls V: Skyrim (`01000A10041EA000`)

Base game v0 and update **v262144** (1.1.177.3285177, SDK 14.3.0, `main` build `771bdfb65f8d0af7203ad4dfeeb548fa`); the profile packs v262144, plus the licence-only Anniversary DLC NSP (`…EB009`, no content). Bethesda's Creation Engine on NVN with Havok; modules `main` and `sdk`. Plays on the Y700 (Android) at **60 fps**: walking, combat, magic, fast travel, building interiors, saves and the GameSir G8+ pad were all played on it in one session on 2026-11-03.

Started as the survey's provisional profile (the this-repo path never had Skyrim), and finished by measurement — the numbers below are what the device said, not guesses.

## What it needs

| Setting | Where | Why |
|---|---|---|
| `mem_reserve 0x440000000` (17 GB), `mem_alias 0x400000000` (16 GB), `mem_stack 0x10000000`, `app_pool 0xCD500000` | [`game.tsv`](game.tsv) | The game maps its own memory: the NPDM declares only 8 MB of system resource and `main` never sets a heap. By the main menu it had reserved 7.4 GB of address regions (24 regions, measured with `DM_ALIAS_SIZE` + `DM_REGIONS`); 16 GB of alias leaves room for cell streaming |
| `present_interval display` | `game.tsv` | The 30 fps cap is only the NVN present interval the game asks for (2, on a fixed 60 Hz tick), and its logic is time-based, so one frame per tick is safe and doubles the rate (see below) |
| `shader_groups /Data/=data /BatchFiles/=batchfiles` | `game.tsv` | The 23,133 shaders are Creation Engine `.fxp` records inside the RomFS's BSA archives (89 of them, version 0x69, 24-byte folder records, LZ4-frame entries), plus 53 built-in records in `main` |
| `bf_want`, `pso_*`, `shader_*` tables | this folder | Generated by the shader split and the NVN translation of v262144 |

No game-specific executable cuts and no `render_cond`: the port's rewrites are the SDK-wide `dm/tools/sdk_patches.py` rules only.

## Frame rate

30 fps was not an engine limiter but the game's own present interval 2 on a 60 Hz tick, so `present_interval display` reached **60 fps with no rewriter work**: 0 dropped frames and p99 16.67 ms at the title screen and in a loaded save, frame time p50 16.64 / p95 17.94 / max 18.80 ms. The player then checked the things a frame-counted game would have doubled — walk pace, NPC animation, combat and magic timing, the in-game clock — and found all of them normal, which is the proof that switch requires.

The budget at 60 is full: frame work p50 **16.54 of 16.67 ms**, GPU busy 12.30 ms, replay 4.46 ms over 2,050 draws (descriptor sets 1.26), queue submit 0.85 ms. Country holds 60; cities and combat drop frames before they stutter, and the headroom to buy is in the replay.

The host's pause menu also carries a live **Frame rate — 60 fps | 30 fps** row (`settings.txt` `rate60`), so a player can drop to the locked 30 for battery or heat without re-porting.

## Memory and streaming

A cell load reads **100–260 MB** out of the data pack — the `DM_FSLOG` of a Whiterun session holds 34,864 reads and 2,237 MB over 376 s, with 78.7% of the reads only 4–16 KB and 67% continuing within 4 KB of the previous read's end, at about 150 MB/s through FUSE while the same pack reads from cache at 2.0–5.3 GB/s. That is what the 200–900 ms load frames are made of: 150–420 ms of NVN→Vulkan replay and 200–850 ms of the guest's own work, never the present path (its queue is 0.0 ms on every hitch). `DM_FADVISE` adds the readahead advice this shape wants; it is off by default.

Footprint settles near 1.6–1.7 GB and stays flat; the alias region maps 2.00 GB of the 3.21 GB pool.

## Packaging

`porter port <game folder> --experimental --install` produces the release APK (**1.85 MB**, `lib/arm64-v8a` only) and the 12.9 GB data pack; adding `--debug` gives the 8.2 MB development build with `DM_CTL` (key presses and screenshots from a shell). The release build was verified on the Y700 on 2026-11-03: 60 fps, 0 dropped frames, the pause menu's Frame rate row present, `DM_CTL` stripped from `env.txt`, and the saves taken in a debug session still listed under `CONTINUE` after the swap — the same package and signer keep the app's data.

## Audio

The game opens a 6-channel `DeviceSink`; its centre and LFE channels are silent and its rear pair is **exactly half the front pair**, so the stereo fold is duplicate-aware (a rear that is a scaled copy of its front is not added a second time). The plain ITU fold added 0.354 × the front (+2.6 dB) of the same music and the player heard it as overdrive/static on both platforms; front-pair-only was clean. `DM_AUDREN_DOWNMIX=all` restores the old fold for an A/B and `=front` plays the front pair alone. `DM_AUDREN_PCM6=<file>` writes the six channels before the fold.

The first sound (the publisher logo/loading music) had whole 5 ms blocks of digital zero in it, heard as clicks/pops. Most of that was the game's **second** `AudioRenderer` (32 voices, opened at boot), which the host used to ignore: its output has a continuous 2 s run across the first renderer's boot holes, and the game **traps at boot** if it is never rendered (`CRASH sig=5`, `main+0x107821c`). The host now renders it once per output frame and uses it only where the first renderer's frame is silent (fill mode, the default; `=add` sums it, `=0` discards the output). That takes the boot holes from 60 to 4 without adding the same logo twice; the player at unity reports **clean from the Skyrim logo onward**. The gritty **Bethesda** stinger is the game's own — the Y700 sounds the same — and a static gain and a soft limiter were tried and removed. Three sub-frame holes around 7.55 s remain in the guest's own mix (quiet); see [the bring-up doc](../../../../docs/BRINGUP_SKYRIM.md), session update 2026-11-06.

## Known gaps

- **Saves live inside the app** (`files/save/Saves`, about 2.6 MB each). On the debug build they can be copied out with `run-as`; on the release build that is refused (`run-as: package not debuggable`), and an uninstall or Clear data deletes them. The manifest carries `ALLOW_BACKUP`, so `adb backup -f saves.ab org.nx2a.t01000a10041ea000` is the only export path the port offers today — a real export/import in the host is still missing.
- **The unexplained crash** was the `DM_VK_PROF` sampling profiler's SIGPROF frame landing on guest registers (fixed in `android/gfx_vk_exec.c`); no crash has recurred since, and a guest store into read-only text is now reported and dropped rather than fatal.
- **No iOS/macOS chain**: the Metal shader libraries for this game have never been built, and the translation chain's tool lock wants a newer Metal than the development Mac has.
